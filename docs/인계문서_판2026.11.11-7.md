작성일 2026-11-11. 이 문서 하나로 새 세션을 시작할 수 있게 쓴다. 판 2026.11.11-5의 인계 문서를 판 2026.11.11-7에 맞춰 고친 것이고, 이전 문서들은 git 기록에 있다.

## 2. 지켜야 할 것

### 2.1 절대 요구사항 (사용자 지정)

1. 어떤 기기에서도 스크롤 없이 한 화면 안에서 게임이 실행되어야 함
2. 모바일 가로 화면에 최적화하되 다른 화면에서도 게임이 잘리면 안 됨
3. 게임 규칙과 조작 방법은 튜토리얼을 통해 설명
4. 기존 게임 규칙과 구조를 임의로 변경하지 않음
5. 사용자 동의 없이 새로운 시스템이나 콘텐츠를 추가하지 않음
6. 수정 전 GitHub의 최신 코드를 반드시 확인
7. 수정 후 코드 검증과 실제 실행 상태 확인
8. 파일 다운로드보다 GitHub Pages를 통한 웹 실행 우선
9. 기존 탄착점 및 셀바운드 프로젝트와 완전히 분리

### 2.2 이번 대화에서 사용자가 확정한 방침

- 휴대폰만 대상으로 한다. PC 버전은 개발하지 않는다.
- 게임은 2.5D로만 진행한다. 2D 화면은 WebGL이 실행되지 않거나 오류가 날 때만 쓰는 비상용이다.
- 전장이 화면 전체를 차지한다. 조작 버튼은 전장 모서리의 아이콘 둘(왼쪽 아래 아이템, 오른쪽 아래 과부하)과 오른쪽 위 톱니바퀴뿐이다. 이동 버튼은 없고 전장을 터치해 옮긴다.
- 전장에 시설 이름 글자를 쓰지 않는다. 튜토리얼에서 설명한다.
- 아이템 칸은 비어 있어도 숨기지 않는다.
- 튜토리얼은 실제 전투로 보여 준다. 과부하와 아이템은 훈련에서 잠그고 실전 중 필요한 순간에 설명한다. 과부하 안내에 적을 따로 추가하지 않는다.
- 진행은 WAVE 표기로 한다. 맵은 WAVE가 진행되며 바뀌고, 맵 모양에는 규칙을 붙인다. 다양한 맵을 원한다.
- 적은 조금 작게, 더 많이. 드물게 레어 적이 나온다.
- 시작 화면은 영상이 먼저 나오고 SKIP 버튼이 있다.
- 아이템은 한 판에 5~8번쯤 나온다. 레어 적은 1.5%, 중간 보스 보상은 유지, 돌파 없는 보상은 장 전체가 무돌파일 때 장 끝에 한 번(2026-11-11 결정).
- 아이템 칸은 아이템 안내가 나올 때까지 잠근다(2026-11-11 결정).

## 3. 게임 내용 (코드에서 확인한 값)

### 3.1 기본 규칙
- 전선 2개(0번 끝에 발전소, 1번 끝에 정비소), 지원 기체 1대, 자동 포탑 2대, 중앙 송신소.
- 적이 방어선을 넘으면 그 전선 시설의 내구도가 줄고 송신소도 피해를 받는다. 시설이 이미 멈춘 전선이면 송신소 피해가 1.7배다. 송신소가 0이면 패배.
- 발전소가 멈추면 이동 대기 1.5배, 정비소가 멈추면 포탑 사격 간격 1.35배.
- 기체: 사거리 155, 피해 19, 간격 0.29초, 이동 대기 2.2초. 포탑: 사거리 165, 피해 14, 간격 0.52초. 과부하: 피해 75, 범위 110, 재충전 11초.
- 모든 거리는 전선 위 1차원 거리다. 전선 길이는 509(방어선 y=608, 기체 y=340, 포탑 y=489).

### 3.2 진행
- WAVE 1-1부터 5-3까지. 앞 숫자가 장, 뒤 숫자가 그 장의 공격 번호. 공격 번호는 시간으로 넘어간다(`WAVES`).
- 장이 끝날 때 강화 하나를 고른다(모두 네 번).
- 3-3과 4-3에 중간 보스, 5-3에 최종 보스. 최종 보스는 체력 1.5배이고 체력이 2/3, 1/3이 될 때 반대 전선으로 넘어간다.
- 적 일정은 손으로 짠 표(`stages`)에 뒤따르는 적을 덧붙인다. 1장은 작은 적 셋마다 하나, 2장부터는 둘마다 하나. 보스 아닌 적의 체력은 0.85배.
- 레어 적은 보스 아닌 적의 1.5%(`RARE_P`). 체력 1.6배. 봇 기준 한 판에 3~4기 나온다.

### 3.3 강화 4종
| 강화 | 내용 | 3단계부터 |
|---|---|---|
| 순환 전원 | 이동 대기 단축, 이동 후 사격 강화, 사거리 증가 | 강화 중 떠난 전선도 사격 |
| 협동 조준 | 한 전선에 머물수록 포탑 가속(이동하면 초기화) | 최대 가속 때 포탑 관통 |
| 비상 축전 | 과부하 피해·범위 증가, 맞힌 수만큼 재충전 단축 | 없음 |
| 잔해 차폐 | 기체가 떠난 전선의 적 감속 | 없음 |

후보 제시 규칙: 발전소가 살아 있으면 순환 전원, 멈췄으면 비상 축전. 정비소가 살아 있으면 협동 조준, 멈췄으면 잔해 차폐. 세 번째 후보는 나머지 둘이 장마다 번갈아 나온다. 두 시설을 다 지키면 비상 축전과 잔해 차폐는 최대 2단계까지만 오른다.

### 3.4 맵 (`MAPS`, `MAP_OF`)
| 장 | 맵 | 모양 | 규칙 |
|---|---|---|---|
| 1 | 직선로 | 직선 | 없음 |
| 2, 5 | 협곡 | y 250~430에서 두 전선이 붙음 | 그 구간 안의 적은 반대 전선에 있어도 과부하에 맞음 |
| 3 | 우회로 | 전선마다 다른 위치에서 두 번 꺾임 | 꺾인 구간 안의 적은 40% 느림 |
| 4 | 굽잇길 | 물결 모양, 두 굽이에서 가까워짐 | 굽이 안의 적은 반대 전선에 있어도 과부하에 맞음 |

전선 길이는 맵과 무관하게 같다. 포탑이 있는 y 440 이후는 휘지 않는다.

### 3.5 아이템 (`ITEMS`, 한 칸)
| 아이템 | 효과 |
|---|---|
| 차단벽 | 기체가 없는 전선의 적 4초 정지 |
| 긴급 수리 | 더 부서진 시설 내구도 +30 |
| 과충전 | 이동 대기와 과부하 재충전 즉시 해제 |
| 임시 포탑 | 기체가 없는 전선에 8초간 포탑 |
| 전파 교란 | 모든 적 5초간 50% 감속 |
| 분신 기체 | 6초간 반대 전선에도 기체 사격 |

얻는 경로: 레어 적 격파, 중간 보스 격파, 한 장(공격 세 번)을 돌파 없이 끝냈을 때 장 끝에 한 번. 종류는 무작위. 칸이 찬 채 레어 적을 잡으면 새 아이템이 즉시 발동한다. 그 밖의 경우 칸이 차 있으면 받지 못한다.

장 보상의 판정(판 2026.11.11-7부터): 그 장에서 적이 한 번도 방어선을 넘지 않았으면(`stageHurt`가 거짓) 마지막 적이 사라진 순간 지급한다. 마지막 장(5장)은 끝나면 판이 끝나므로 지급하지 않는다. 강화 선택 화면의 피해 보고에 "돌파 없이 방어 · 아이템 획득: ○○" 또는 "아이템 칸이 차 있어 보상을 받지 못했습니다"가 한 줄 나온다(`stageGift`).

### 3.6 안내 흐름
- 시작 화면: 영상 1회(자막 세 줄, SKIP) → 제목과 버튼("훈련 후 작전 시작", "바로 작전 시작"). 자동 재생이 막히면 재생 버튼.
- 훈련: 기체가 묶인 채 발전소가 무너지고 송신소가 끊기는 것을 보여 준 뒤, 전선을 옮겨야 막을 수 있는 상황을 두 번 준다. 건너뛰기 버튼 있음. 과부하와 아이템은 잠김.
- 실전 안내(각각 브라우저당 한 번, `localStorage`의 `relayLearn`): 과부하(한 전선의 범위 안에 적 3기가 모일 때, 2장부터는 2기), 아이템(처음 얻었을 때), 새 맵(그 맵을 처음 시작할 때).
- 안내는 한 번에 하나만 나온다. 한 안내가 끝난 뒤 실제 진행 4초(`LESSON_GAP`)가 지나야 다음 안내가 나온다. 겹치면 새 맵, 과부하, 아이템 순이다. 아이템 칸은 아이템 안내가 나올 때까지 잠긴다(`itemLocked`). 봇으로 재 보면 과부하 안내는 대개 1장 14초쯤, 놓치면 23초쯤에 나온다.

## 4. 구조

| 파일 | 내용 |
|---|---|
| `index.html` | 규칙, 화면 틀, 시작 화면, 훈련, 안내, 설정, 비상용 2D 화면 |
| `r3d/core.js` | 2.5D의 중심. 카메라와 화면 맞춤, 화질 자동 하향, 휜 전선 좌표(`off`, `laneZAt`), 터치 판정(`laneAt`) |
| `r3d/env.js` | 지형, 도로, 조명. `bendLanes`가 도로·연석·가로등을 휜다 |
| `r3d/base.js` | 시설, 송신소, 포탑 |
| `r3d/units.js` | 기체와 적. 레어 적 발광, 크기 배율 |
| `r3d/fx.js` | 사격, 폭발, 과부하 등 효과 |
| `r3d/hud.js` | 겹쳐 그리는 표시. 체력 막대, 예고 칸, WAVE 표기, 이동 대기 고리, 레어 표시, 아이템 효과 표식 |
| `r3d/three.min.js` | three.js r160 |
| `media/` | 시작 화면 영상(세로·가로), 대기 그림, 음악 |
| `tools/` | 시험·제작 도구(7장) |

- 화면 쪽은 `window.__relay`(코드 안 `G3`)를 읽기만 한다. 사건은 `G3.events`로 받는다.
- 세로 화면은 기지 뒤에서 내려다보는 시점(`behind`), 가로 화면은 옆에서 내려다보는 시점(`side`).
- 주소 끝 `?2d=1`은 비상용 2D 강제, `?q=0|1|2`는 화질 고정(시험용).
- 화질은 프레임이 느리면 자동으로 내려가고 다시 올라가지 않는다. 2D로 넘어가지 않는다.
- 저장: `relayPrefs`(속도, 음량, 밝기, 음악), `relayLearn`(훈련, 과부하, 아이템, 맵별 안내 여부).
- 주요 상태 이름: `drill`, `lesson`, `lessonQuiet`, `holdState`, `pulseLock`, `liveRun`, `item`, `aid`, `map`, `stageHurt`, `stageGift`.

## 5. 확인된 것과 안 된 것

자동 시험으로 통과한 것(판 2026.11.11-7):
- 훈련과 과부하 안내를 실제 터치로 끝까지 진행(2.5D 가로·세로, 2D 세로), 스크롤 없음
- 시작 화면 흐름(재생, 종료 후 메뉴, SKIP, 자동 재생 거부 시 버튼)
- 설정 창(정지, 속도, 밝기, 음량, 뒤로가기, 저장, 터치 이동, 과부하 버튼)
- 아이템 6종의 효과, 레어 격파 보상, 최종 보스의 전선 이동
- 맵 규칙 두 가지와 새 지형 안내
- 장 단위 보상 판정(돌파 없는 장은 장 끝에 한 번 지급, 돌파가 있으면 미지급, 칸이 차 있으면 미지급과 화면 표시, 마지막 장 미지급)과 안내 간격, 아이템 칸 잠금
- 과부하 범위 틀: 네 맵의 가로·세로 화면을 찍어 눈으로 확인(자동 판정은 없음)
- WebGL 오류·컨텍스트 손실 시 2D 전환
- 같은 난수와 조작에서 2.5D로 그리든 안 그리든 게임 상태가 같음

확인하지 못한 것:
- **실제 휴대폰에서의 모든 것**: 프레임 속도, 적과 기체의 크기와 선명도, 터치감, 뒤로가기, 앱 내 브라우저, 영상 자동 재생
- **소리**: 음악과 효과음을 들어 보지 못했다. 코드로 합성했다
- **사람 기준 난이도와 재미**
- **`base.js`의 독립 검토**, 통합본 전체의 교차 검토

## 6. GPT 분석(판 2026.11.11-5 대상)과 대조한 결과

GPT가 짚은 세 가지는 모두 판 2026.11.11-5의 코드에서 사실로 확인했다. 둘째는 고쳤고, 첫째는 빈도를 줄인 뒤 드물어졌다.

| 지적 | 확인 | 측정 |
|---|---|---|
| 칸이 찬 채 레어 적을 잡으면 즉시 발동해 낭비될 수 있음 | 사실 | 판 2026.11.11-5: 아이템을 쓰지 않는 봇 기준 한 판에 약 13번. 판 2026.11.11-7: 쓰지 않는 봇 2.9번, 필요할 때 쓰는 봇 0.2번 |
| 웨이브 보상이 이전 웨이브의 적이 남아 있어도 판정됨 | 사실이었다. 판 2026.11.11-7에서 시간 기준 지급을 없애고 장 단위 보상으로 바꿈(3.5절) | 고치기 전: 한 판 평균 8.3번 지급 중 2.8번은 적이 남은 상태였고, 그중 0.6~0.9번은 그 적이 나중에 돌파함 |
| 강화 불균형 | 사실. 3.3절 참조 | 미측정 |

측정하면서 새로 드러난 것:
- **아이템이 너무 자주 나왔다.** 판 2026.11.11-5는 한 판에 지급 기회가 27번쯤이었고, 받자마자 쓰는 봇은 25.6개를 받았다. 판 2026.11.11-7(24판 평균)은 지급 기회 8.1~8.9번(돌파 없는 장 2.8~3.3, 중간 보스 2, 레어 3.2~3.7)이고, 실제로 받는 것은 필요할 때 쓰는 봇 8.5개, 받자마자 쓰는 봇 8.0개다. 목표 5~8번의 위쪽 끝이다. 봇은 사람보다 돌파가 적으므로 사람은 이보다 적게 받을 것으로 보지만 재 보지는 못했다.
- **봇이 16판을 모두 이긴다.** 위협이 큰 전선으로 옮기고 2기 이상에 과부하를 쓰는 단순한 봇이다. 반응 간격 0.2초, 0.8초, 1.6초 모두 같다. 평균 돌파 약 4회, 송신소 약 80. 판 2026.11.11-3에서도 16판 전승이었다.

GPT가 확인하지 못한 것: 2.5D 화면(시험 환경에서 WebGL 차단), 실제 휴대폰. 묶음(zip)에 `tools/`가 없다는 지적은 맞고 저장소에는 있다.

## 7. 방향

지금은 콘텐츠를 더 넣을 때가 아니라 넣은 것이 맞물려 돌아가는지 확인할 때다. 이 점은 GPT의 판단과 같다.

게임의 중심은 기체 한 대로 두 전선을 막는다는 제약이다. 플레이어의 판단은 네 가지다. 옮길 것인가 버틸 것인가, 과부하를 언제 쓸 것인가, 아이템을 아낄 것인가 쓸 것인가, 어떤 강화를 고를 것인가. 맵 규칙과 아이템은 이 판단을 늘리려고 넣었다. 실제로 늘었는지, 복잡해지기만 했는지는 사람이 해 봐야 안다.

## 10. 시험할 것

### 10.1 실제 휴대폰에서 (사용자)
1. 시작 영상이 자동으로 나오는가. 안 나오면 "터치해서 영상 재생" 버튼이 보이는가
2. 음악과 사격음이 들을 만한가
3. 가로 화면에서 적과 기체가 충분히 크고 구분되는가. 레어 적이 눈에 띄는가
4. 전선을 터치했을 때 의도한 전선으로 가는가. 휜 맵에서도 그런가
5. 적이 몰릴 때 끊기지 않는가. 화질이 내려간 뒤에도 볼 만한가
6. 시설 피해와 송신소 내구도를 글자 없이 알아볼 수 있는가
7. 강화 선택 창과 설정 창이 작은 화면에서 읽히는가
8. 뒤로가기를 누르면 설정이 열리는가(안드로이드, 앱 내 브라우저)
9. 훈련이 길거나 답답하지 않은가
10. 맵 규칙을 설명 한 번으로 이해할 수 있는가. 협곡에서 과부하를 일부러 맞춰 쓰게 되는가
11. 아이템을 아껴 두게 되는가, 받자마자 쓰게 되는가

### 10.2 자동 시험 (`tools/`, Node와 Playwright 필요)
| 명령 | 확인하는 것 |
|---|---|
| `node tools/drilltest.js <폴더> <출력 폴더>` | 훈련, 아이템 안내, 과부하 안내 전체 진행 |
| `node tools/title_test.js <출력 폴더>` | 시작 화면 흐름. 먼저 `python3 -m http.server 8765`를 게임 폴더에서 띄워야 함 |
| `node tools/settings3d.js <폴더>` | 설정 창 |
| `node tools/item_test.js <폴더>` | 아이템, 레어 보상, 최종 보스 |
| `node tools/map_test.js <폴더>` | 맵 규칙과 새 지형 안내 |
| `node tools/fallback3d.js <폴더> <출력 폴더>` | 2D 비상 전환 |
| `node tools/purity3d.js <폴더> [크기]` | 2.5D가 규칙에 영향을 주지 않는지(8분쯤 걸림) |
| `node tools/bal_scan.js <폴더> [판 수]` | 봇 승률, 평균 돌파 |
| `node tools/grant_scan.js <폴더> [판 수]` | 한 판의 아이템 지급 기회와 경로, 실제로 받은 횟수, 칸이 차서 즉시 발동하거나 못 받은 횟수. 봇 셋(쓰지 않음, 필요할 때 씀, 받자마자 씀)으로 잰다 |
| `node tools/reward_test.js <폴더>` | 장 단위 보상 판정, 강화 화면의 보상 표시, 안내 간격, 아이템 칸 잠금 |

`<폴더>`는 절대 경로로 준다(`$PWD`). 상대 경로를 주면 대부분의 도구가 페이지를 열지 못한다. 시험은 파일로 열기 때문에 음악 파일을 받지 못한다는 오류가 한 줄 나온다. 정상이다. `title_test.js`의 자동 재생 차단 모사는 `play()` 거부와 함께 `autoplay` 속성도 지운다. 속성을 남겨 두면 시험용 브라우저가 속성만으로 재생을 시작해 그 항목이 실패한다(판 2026.11.11-5도 같았다). `shot3d.js`의 `practiceMove`, `practicePulse` 장면은 없어진 예전 튜토리얼용이다. `adapt3d.js`는 2D 자동 전환을 없애기 전 기준이라 결과 해석이 달라졌다. `sim_bal_3.js`는 예전 판용이다.

## 12. 실험판 (`lab/`): 소리와 타격감

2026-11-11에 사용자가 "소리가 전부 가볍고 단조롭다, 타격감은 있는 것까지 모두 고쳤으면 한다"고 평가했다. 본 게임은 건드리지 않고 `lab/` 폴더에 실험판을 따로 만들었다. 주소는 https://sylbster-cpu.github.io/Defense/lab/ 이고 판 표기는 `2026.11.11-7-lab3`이다. 규칙은 판 2026.11.11-7과 같다.

### 12.1 연구에서 나온 것
- 기준으로 공개 게임 두 편의 소리를 쟀다(Mindustry 무기음 64개와 폭발음 32개, Warzone 2100 무기음 29개와 폭발음 11개. 둘 다 GPL이라 파일은 쓰지 않고 수치만 쟀다).
- 사격음 길이(가장 큰 순간에서 20 dB 줄 때까지, 중앙값): 본 게임 0.03초, 기준 0.62초와 0.76초. 폭발음: 본 게임 0.08초, 기준 1.0초와 1.5초.
- 평균 음량: 본 게임 사격음 -44 dBFS, 기준 -25와 -14. 400 Hz 아래 에너지: 본 게임 6%, 기준 83%와 55%.
- 본 게임에는 탄착음, 배경음, 변주가 없다. Mindustry는 포탑 소리를 0.9~1.1배 높이로 바꿔 재생한다(소스 코드에서 확인).
- 화면 흔들림은 가로 844×390에서 과부하 ±1.2px에 0.02초, 가장 큰 시설 붕괴도 ±2.6px에 0.11초였다. 타격 정지, 일반 피격의 밀림, 진동은 없었다.

### 12.2 실험판에 넣은 것
| 파일 | 내용 |
|---|---|
| `lab/sfx.js` | 소리 엔진. 소리마다 층(시작, 몸통, 저음, 기계음, 꼬리)을 겹치고 잔향을 붙여 배열로 미리 만든다. 21종 40개, 자주 나는 소리는 2~4가지 변형. 배경음 6초 반복. 브라우저와 Node 양쪽에서 돈다 |
| `lab/index.html` | 판 2026.11.11-7의 `index.html`에 소리 재생(`sfx`, `sfxKill`, `sfxHit`, `sfxAmb`), 타격 정지(`hitStop`, `stopTick`), 진동(`buzz`)을 넣은 것. 타격 정지는 `loop` 안에서 `update`를 건너뛰는 방식이라 규칙에 영향이 없다 |
| `lab/r3d/core.js` | 화면 흔들림을 다시 썼다. 사건이 세기를 더하고, 세기의 제곱 × 14px만큼 화면 평면에서 부드럽게 흔들린다. `fxScreen`(화면 번쩍임 값) |
| `lab/r3d/fx.js` | 흔들림 세기, 피격 섬광과 불꽃, 사격 궤적 굵기, 화면 번쩍임 지시 |
| `lab/r3d/units.js` | 일반 피격 때 뒤로 밀리고 눌리는 반응(그림만) |
| `lab/r3d/base.js` | 포탑 반동과 포구 섬광 확대 |
| `lab/r3d/hud.js` | 과부하·큰 폭발의 흰 번쩍임, 돌파의 붉은 가장자리 |

`three.min.js`, `env.js`, `media/`는 본 게임의 것을 그대로 불러 쓴다. 설정과 안내 기록(`localStorage`)은 본 게임과 같이 쓴다.

값: 타격 정지는 과부하 0.07초, 보스 큰 폭발과 시설 붕괴 0.1~0.11초, 돌파 0.04초(0.6초에 한 번). 흔들림 세기는 과부하 0.7, 돌파 0.6, 보스·붕괴 1, 대형 격파 0.33, 중형 0.2. 진동은 안드로이드 브라우저에서만 된다.

사용자 평가(2026-11-11): 새 소리는 기체 사격음만 빼고 마음에 든다. 기체 사격음은 합성으로 세 번 만들었지만(첫 안, 후보 A~C, 후보 D~F) 모두 맞지 않았다. A~C는 "가볍고 통통 튄다"는 평가였고, 재 보니 200 Hz 근처의 한 음이 에너지의 67~79%를 차지했다. 사용자가 "새로운 방식으로 만들자", "총보다 조금 더 대포처럼"이라고 해서 방식을 바꿨다.

지금 후보 G, H, I, J는 녹음된 소리를 재료로 쓴다. Freedoom 프로젝트의 권총, 산탄총, 2연발 산탄총, 폭발 소리(`dspistol`, `dsshotgn`, `dsdshtgn`, `dsbarexp`)를 16 kHz로 다듬어 `lab/sfx.js`의 `SAMPLES`에 넣고, 재생 속도를 낮춰 깊게 만든 뒤 잔향을 붙였다(`samp`). 길이는 0.56~0.90초다. 실험판 기본은 G(권총을 낮춘 경포)이고 주소 끝에 `?drone=h`(산탄총 포성), `?drone=i`(2연발, 가장 큼), `?drone=j`(권총에 폭발 저음, 가장 긺)를 붙이면 나머지를 들을 수 있다. 판 표기는 `2026.11.11-7-lab3`.

Freedoom의 소리는 3조항 BSD 라이선스다. 저작권 고지를 함께 두어야 하며 `lab/FREEDOOM-NOTICE.txt`와 `lab/sfx.js` 끝에 넣었다. 본 게임에 옮길 때도 고지를 함께 옮긴다. 외부 자료를 쓰는 것이므로 본 게임 반영 전에 사용자 승인을 받는다. 사용자가 하나를 고르면 나머지 후보와 쓰지 않는 재료는 지운다.

교훈: 길이, 음량, 대역 분포만 맞춰서는 "통통 튄다" 같은 성질을 잡지 못한다. 한 음에 몰린 정도를 `tools/sound_tone.py`로 함께 잰다. 작업자는 소리를 듣지 못하므로 사용자의 표현을 잴 수 있는 항목으로 옮기는 과정이 매번 필요하고, 합성으로 여러 번 빗나가면 녹음 재료로 바꾸는 편이 빠르다.

### 12.3 확인된 것과 안 된 것
- 실험판으로 10.2의 시험(보상, 아이템, 맵, 설정, 2D 전환, 훈련, 봇, 2.5D 순수성)과 `tools/lab_check.js`를 돌려 모두 통과했다. 봇은 16판 전승이고 2.5D 순수성 시험에서 게임 상태가 같았다.
- 소리가 듣기에 좋은지, 연출이 손에 맞는지는 확인하지 못했다. 소리는 수치(길이, 음량, 대역)만 기준 범위에 맞췄다. 사용자가 휴대폰에서 들어 보고 해 봐야 한다.
- 시험용 브라우저는 초당 10프레임쯤이라 흔들림 크기는 설계값(과부하 약 7px)보다 작게 재진다.
- 소리 비교판(Claude 아티팩트)에 본 게임 소리와 실험판 소리를 나란히 들을 수 있게 해 두었다.
