- 저장소: `sylbster-cpu/Defense`, 브랜치 `main` (GitHub Pages로 배포)
- 실행 주소: https://sylbster-cpu.github.io/Defense/
- 이 문서는 이전 인계 문서(2026-11-10-2)를 대체한다. 밸런스 수치와 봇 표는 6장에 옮겨 적었다.

## 00. 최신 변경 (판 2026.11.11-5). 다른 절과 다르면 이 절이 맞다

사용자 지시로 규칙과 콘텐츠가 크게 늘었다. 5장과 6장의 수치와 밸런스 표는 이 판 이전 것이다.

- **진행 표기**: WAVE 1-1부터 5-3까지. 장(1~5)이 예전 작전, 뒤 숫자가 공격 번호다. 3-3과 4-3에 중간 보스, 5-3에 최종 보스. 강화 선택은 각 장이 끝날 때.
- **최종 보스**: 체력 1.5배, 크게 그려짐. 체력이 2/3과 1/3이 될 때 반대 전선으로 넘어간다.
- **적 수와 크기**: 1장은 작은 적 셋마다, 2장부터는 둘마다 한 기가 뒤따라 나온다. 보스 아닌 적의 체력은 0.85배(`HP_SCALE`). 그림은 10% 작게.
- **레어 적**: 보스 아닌 적의 5%(`RARE_P`). 체력 1.6배, 몸이 빛나고 머리 위에 금색 표시. 잡으면 아이템을 준다. 칸이 차 있으면 그 아이템이 즉시 발동한다.
- **아이템**(한 칸, 왼쪽 아래 버튼): 차단벽(기체 없는 전선 4초 정지), 긴급 수리(더 부서진 시설 +30), 과충전(이동·과부하 대기 즉시 해제), 임시 포탑(기체 없는 전선에 8초), 전파 교란(전체 5초 감속 50%), 분신 기체(6초간 반대 전선 사격). 얻는 경로는 레어 적, 중간 보스, 방어선 돌파 없이 넘긴 공격. 처음 얻을 때 한 번 정지하고 설명한다.
- **맵**(장마다 바뀜, `MAPS`와 `MAP_OF`): 1장 직선로, 2장 협곡, 3장 우회로, 4장 굽잇길, 5장 협곡. 전선 길이는 그대로이고 구간에서 중앙 쪽으로 휜다.
  - 협곡·굽잇길: 두 전선이 붙는 구간 안의 적은 반대 전선에 있어도 과부하에 맞는다.
  - 우회로: 꺾인 구간 안의 적은 40% 느리다. 구간 위치가 전선마다 다르다.
  - 처음 만나는 맵은 시작할 때 한 번 정지하고 규칙을 설명한다.
- **소리**: 포탑·기체 사격, 격파, 폭발음을 낮아지는 음과 걸러낸 잡음의 조합으로 바꿨다.
- **구현 위치**: 규칙은 `index.html`(`MAPS`, `ITEMS`, `aid`, `grantItem`, `aidStep`, `spawn`, `damageEnemy`). 휘는 전선은 `core.js`의 `off`·`laneZAt`, 도로를 휘는 것은 `env.js`의 `bendLanes`. 아이템 표시와 레어 표시는 `hud.js`.
- **시험**: `tools/item_test.js`, `tools/map_test.js`, `tools/bal_scan.js` 추가.
- **밸런스**: `bal_scan.js`의 봇은 이 판에서 16판 모두 승리한다(이전 판도 같음). 평균 돌파 약 4회, 송신소 약 80. 사람 기준 난이도는 확인하지 못했다. 강화 4종의 후보 제시 규칙과 3단계 효과 불균형은 그대로다.
- **알려진 부족**: 과부하 범위 점선 틀은 휜 전선을 따라가지 않고 직사각형이다. 아이템 효과 표시는 화면 위 표식 수준이다(3D 모형 없음). 휜 맵에서는 중앙 분리대를 숨긴다. 비상용 2D 화면에는 맵 모양, 아이템 효과, 레어 표시가 그려지지 않는다.

## 0. 최신 변경 (판 2026.11.11-3). 아래 절과 다르면 이 절이 맞다

사용자 결정:
- 게임은 2.5D로만 진행한다. 설정의 2.5D·2D 전환을 없앴다. 느린 기기에서도 2D로 넘어가지 않고 최저 화질에 머문다. 2D 화면은 WebGL이 아예 안 되거나 오류가 날 때만 쓰는 비상용이다(`?2d=1`로 강제 가능).
- 아이템 칸은 숨기지 않는다.
- 과부하 안내는 추가 적 없이 원래 일정의 무리에 붙인다. 한 전선에 과부하 범위 안의 적이 3기 모이면(작전 1에서는 정비소 전선의 약 23초 지점) 정지하고 안내한다. 작전 2부터는 2기면 된다. 기체가 다른 전선에 있으면 먼저 옮기게 한다.
- 시작 화면은 영상이 먼저 한 번 재생되고(자막 세 줄, `SKIP »` 버튼), 끝나면 제목과 시작 버튼이 나온다. 자동 재생이 막힌 기기에서는 "터치해서 영상 재생" 버튼이 나온다.
- PC 버전은 개발하지 않는다.

그 밖의 변경:
- 훈련 중 왼쪽 위에 "훈련 건너뛰기 »" 버튼.
- 전선 터치 경계를 화면 절반이 아니라 그려진 중앙 분리대에 맞췄다(`core.js`의 `laneAt`).
- 설정 창은 화면이 낮으면 스크롤 대신 축소된다.
- 예전 설명식 튜토리얼과 연습 코드, 숨겨 두었던 버튼과 현황 패널을 지웠다. 예전 화면용 CSS 일부는 남아 있다.
- 9장 "고칠 것"의 2번, 4번은 끝났다. 1번(2D 보완)은 2.5D 전용 결정으로 우선순위가 낮아졌다.

사용자가 제시한 다음 방향(아직 구현하지 않음):
1. 진행 표기를 WAVE 1-1부터 시작하는 방식으로 바꾸고, 진행 중 중간 보스, 마지막 WAVE에 최종 보스.
2. WAVE가 진행되며 맵 변경. 전선 두 개는 유지하되 모양을 바꾼다. 사용자 스케치 세 가지: (가) 가운데에서 두 전선이 가까워지는 형태, (나) 네모난 우회로가 있는 형태, (다) 물결 모양.
3. 아이템. 내용은 미정이고 추천안을 제시한 상태다.

맵 변경을 위해 필요한 일: 지금은 전선이 직선이라는 가정이 `core.js`(좌표 변환, 카메라 맞춤, 터치 판정), `env.js`(도로, 가로등, 분리대), `base.js`(포탑 위치), `units.js`·`fx.js`·`hud.js`(범위 표시, 예고 칸)에 들어 있다. 전선 위 거리 → 화면 위치를 돌려주는 경로 함수를 `core.js`에 두고 나머지가 그것만 쓰게 바꿔야 한다. 규칙은 전선 위 1차원 거리로 계산하므로 모양만 바꾸면 규칙은 그대로다.

## 1. 절대 요구사항 (사용자 지정, 계속 유효)

1. 어떤 기기에서도 스크롤 없이 한 화면 안에서 게임이 실행되어야 함
2. 모바일 가로 화면에 최적화하되 다른 화면에서도 게임이 잘리면 안 됨
3. 게임 규칙과 조작 방법은 튜토리얼을 통해 설명
4. 기존 게임 규칙과 구조를 임의로 변경하지 않음
5. 사용자 동의 없이 새로운 시스템이나 콘텐츠를 추가하지 않음
6. 수정 전 GitHub의 최신 코드를 반드시 확인
7. 수정 후 코드 검증과 실제 실행 상태 확인
8. 파일 다운로드보다 GitHub Pages를 통한 웹 실행 우선
9. 기존 탄착점 및 셀바운드 프로젝트와 완전히 분리

작업 순서: 승인된 것만 구현 → 시험 → 화면 확인 → `main` 반영. `main`에 올릴 때마다 `index.html`의 `BUILD` 상수를 바꾼다.

## 3. 현재 게임의 모습

### 3.1 시작 화면
- 전체 화면에 게임 영상이 반복 재생된다(세로용 540×960, 가로용 960×540, 각 12초).
- 제목, 한 줄 소개, 버튼 둘("훈련 후 작전 시작", "바로 작전 시작"), 음악 켜기·끄기, 판 번호.
- 훈련을 한 번 마친 브라우저에서는 "바로 작전 시작"이 주 버튼이 된다.
- 음악은 20초 반복곡이다. 브라우저 정책상 첫 터치 뒤에 소리가 난다. 게임을 시작하면 음악이 줄어들며 멈춘다.

### 3.2 훈련 (튜토리얼)
실제 규칙 위에서 돌아가는 연출된 전투다. 설명이 뜨면 게임이 멈추고, 요구한 행동을 하면 이어진다.

1. 기체가 정비소 전선에 묶인 채 발전소 전선으로 적이 몰려온다. 발전소가 멈추면 정지하고 설명한다(시설 내구도 막대, 발전소 정지 시 이동 대기 1.5배, 정비소 정지 시 포탑 사격 느려짐).
2. 계속 밀려 송신소가 끊기면 정지하고 설명한다(시설이 멈춘 전선의 적은 송신소에 1.7배 피해, 송신소 0이면 실패).
3. 처음부터 다시. 정비소 전선에 적이 몰리면 정지하고 그쪽을 터치해 옮기게 한다. 이어서 발전소 전선으로 되돌아가게 한다.
4. 끝 설명(작전 다섯 번, 강화 선택, 승리 조건) 뒤 작전 1로 넘어간다.

훈련 중 과부하 버튼과 아이템 칸은 잠겨 있고 설명하지 않는다.

### 3.3 과부하 실전 안내
- 과부하를 배운 적 없는 브라우저에서는 작전 1 시작 때 과부하 버튼이 잠겨 있다.
- 작전 1의 9초 시점에 기체가 있는 전선으로 빠른 적 7기를 촘촘히 보낸다. 무리가 과부하 범위에 들어오면 정지하고 ✳ 버튼을 누르게 한다. 기체가 다른 전선에 있으면 먼저 옮기게 한다.
- 한 번 배우면 다시 나오지 않는다. **이 7기는 원래 적 일정에 없던 추가 적이다.** 첫 판의 작전 1 난이도에만 영향을 준다.

### 3.4 전투 화면
- 왼쪽 위: "작전 03 / 05 · 공격 1 / 03". 위 가운데: 송신소 내구도(● 막대와 숫자). 오른쪽 위: 톱니바퀴.
- 왼쪽 아래: 아이템 빈칸(반응 없음). 오른쪽 아래: 과부하(재충전 중 남은 초와 둘레 고리).
- 건물 옆 막대가 시설 내구도. 기체 둘레 고리가 이동 대기 시간. 전선 입구의 칸이 곧 나올 적.
- 세로 화면은 기지 뒤에서 내려다보는 시점, 가로 화면은 옆에서 내려다보는 시점.

## 4. 구조

| 파일 | 내용 |
|---|---|
| `index.html` | 게임 전체(규칙, 2D 화면, 시작 화면, 훈련, 설정). 단일 스크립트 |
| `r3d/three.min.js` | three.js r160 (라이선스 `r3d/THREE-LICENSE.txt`) |
| `r3d/core.js` | 2.5D 화면의 중심. 카메라, 화면 맞춤, 화질 자동 조절, 2D 전환 |
| `r3d/env.js` `base.js` `units.js` `fx.js` `hud.js` | 환경, 기지·포탑, 기체·적, 효과, 겹쳐 그리는 표시 |
| `media/title-p.mp4` `title-l.mp4` `title-*.jpg` | 시작 화면 영상과 대기 그림 |
| `media/intro.mp3` | 시작 화면 음악(24.5초 파일, 3초~23초 구간을 반복) |
| `tools/` | 시험·제작 도구(8장) |

- 규칙과 화면은 분리되어 있다. 2.5D 쪽은 `window.__relay`(코드 안 이름 `G3`)를 읽기만 하고, 사건은 `G3.events`로 받는다.
- 주소 끝 `?2d=1`은 2D 강제, `?q=0|1|2`는 화질 고정.
- 저장되는 것(브라우저 `localStorage`): `relayPrefs`(속도, 음량, 밝기, 화면, 음악), `relayLearn`(훈련 완료 여부, 과부하 학습 여부).
- 주요 상태: `drill`(훈련 진행), `lesson`(과부하 안내 대기), `holdState`(설명 중 정지와 요구 행동), `pulseLock`(과부하 잠금), `settingsOpen`.
- 훈련의 적 배치는 `DRILL` 상수, 과부하 안내 시점과 적 수는 `LESSON_AT`, `LESSON_PACK`.

## 5. 규칙 (코드에서 확인한 값)

- 전선 2개(0 발전소, 1 정비소), 지원 기체 1대, 자동 포탑 2대, 작전 5번, 작전당 공격 3번, 강화 선택 4번.
- 적이 방어선을 넘으면 그 전선 시설 내구도가 줄고 송신소도 피해를 받는다. 시설이 이미 멈춘 전선이면 송신소 피해가 1.7배(올림).
- 발전소가 멈추면 이동 대기 1.5배. 정비소가 멈추면 포탑 사격 간격 1.35배.
- 기본값: 이동 대기 2.2초, 과부하 피해 75, 범위 110, 재충전 11초.
- 강화: 순환 전원, 협동 조준, 비상 축전, 잔해 차폐. 순환 전원과 협동 조준은 3단계부터 새 효과(떠난 전선 사격, 포탑 관통).
- 이번 대화에서 규칙 코드에 넣은 것은 두 가지다. 훈련 중에는 공격 전환 알림과 패배 판정을 훈련 쪽이 가로챈다. 과부하 안내용 추가 적 7기가 첫 판 작전 1에 들어간다.

## 6. 밸런스 (판 2026.11.10-2에서 측정, 이후 규칙 수치는 그대로)

봇 48판 승률(%). 순서는 보통 속도 봇 최적 조작 / 구성과 맞지 않는 조작 / 매우 느린 봇 최적 조작.

| 구성 | 보통 최적 | 맞지 않는 조작 | 매우 느린 최적 |
|---|---|---|---|
| 순환 4 | 87 | 14 | 58 |
| 협동 4 | 78 | 28 | 82 |
| 순환 3 + 협동 1 | 100 | 44 | 78 |
| 순환 2 + 협동 2 | 83 | 65 | 61 |
| 분산 | 79 | 73 | 78 |
| 순환 2 + 잔해 2 | 74 | 14 | 53 |

남은 문제: 혼합 구성이 특화 구성과 비슷하게 강함. 잔해 차폐가 약함. 비상 축전과 잔해 차폐에는 3단계 효과가 없음. 난이도를 올리지 않았음.

사용자 확인 없이 들어가 결정이 필요한 것: 포탑 관통 효과, 협동 조준 상승 속도 하향, 비상 축전 범위 조정.

## 7. 확인한 것과 확인하지 못한 것

통과한 시험(판 2026.11.11-2):
- 훈련과 과부하 안내를 실제 터치로 끝까지 진행(2.5D 가로·세로, 2D 세로). 잠긴 버튼, 틀린 쪽 터치 무시, 스크롤 없음 포함.
- 설정 창(정지, 속도, 화면 전환, 밝기, 음량, 뒤로가기, 저장, 터치 이동, 과부하 버튼).
- 2.5D가 오류를 내거나 그래픽 컨텍스트를 잃으면 2D로 전환.
- 같은 난수와 같은 조작으로 5개 작전을 돌렸을 때 2.5D로 그린 경우와 그리지 않은 경우의 게임 상태가 같음.
- 시작 화면 영상과 음악이 웹 서버에서 재생·해독됨.

확인하지 못한 것:
- **실제 휴대폰에서의 모든 것.** 프레임 속도, 색감, 터치감, 뒤로가기, 앱 내 브라우저, 아이폰의 영상 자동 재생.
- **음악의 듣기 품질.** 코드로 합성했고 들어 보지 못했다. 파형과 주파수 그림만 확인했다.
- **밸런스 봇 재측정.** 2.5D 이후 다시 돌리지 않았다.
- **기지 부품(`base.js`)의 독립 검토와 통합본 전체 교차 검토.** 사용량 한도로 하지 못했다.

## 9. 남은 일

고칠 것:
1. 2D 화면이 새 배치에 덜 맞는다. 세로에서 전장이 화면 가운데에만 나오고, 이동 대기 고리가 없다.
2. 예전 튜토리얼 코드(`tutorialSteps`, `showTutorial`, `startPractice` 등)와 숨긴 화면 요소(`.controls`, `.right`, `.inline-help`)가 쓰이지 않은 채 남아 있다. 지워야 한다.
3. 아이템 칸이 빈칸인 채 보인다. 아이템을 만들 때까지 숨길지 정해야 한다.
4. 훈련을 중간에 건너뛰는 방법이 없다.

정할 것:
1. 아이템의 내용, 개수, 사용 방식. 그 뒤 아이템 실전 안내를 과부하 안내와 같은 방식으로 넣는다.
2. 과부하 안내용 추가 적 7기를 유지할지, 원래 적 일정 안에서 자연스러운 순간을 잡을지.
3. 시작 화면 음악과 영상을 실제로 듣고 본 뒤 고칠 점.
4. 6장의 밸런스 문제와 확인 없이 들어간 세 가지.
